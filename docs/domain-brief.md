# Quorum — Domain Brief (governance and voting-integrity review)

The source for vocabulary, the synthetic association, the rule codes, the threshold vocabulary, the receipt and commitment scheme, the golden cases and the kickoff measurements. Shares are integer basis points, money is integer cents, timestamps are strings (D-8). Every rule in §4–§8 is implemented in `tools/tallylib.py`; every golden case in §9–§10 is printed by `tools/golden_answers.py` and ends with `OK`; every number in §11 is printed by `tools/reference_tally.py` on the frozen fixtures in §12. Items marked **[verify]** are conventions, not facts about any real bylaws; each has a D or O entry in `decisions.md`.

## 1. Product scope

Larkspur Commons Condominium Association (invented): 120 units in two buildings, 138 synthetic owners, one annual meeting on 2026-11-14 with two elections and four resolutions, 46 proxies, 109 ballots, and an eleven-month dues ledger. The product tallies the meeting, proves the tally, and (Phase 3) keeps the dues ledger and the violation workflow.

Left out: nominations, minutes, e-signatures, payment collection, liens, architectural review, real bylaws (`decisions.md` §Not modeled).

## 2. Vocabulary

| Term | Meaning here |
|---|---|
| Unit | The thing that votes. 120 of them; `A-101`..`B-610`. |
| Share | A unit's ownership interest in basis points (1/100 of a percent); the 120 shares sum to exactly 10000 at every as-of date (D-9). From the declaration **[verify: real declarations state percentages to 2–4 decimals]**. |
| Owner / member | A person on an ownership row for some unit as of the record date. Co-owners share one unit's single ballot (D-10). |
| Record date | The date eligibility, ownership and shares are read as of. Here 2026-11-14. |
| Direct ballot | A ballot cast by an owner of the unit, in the room or electronically in the window; `via_proxy_id` empty. |
| Proxy | A grant by a unit's owner (grantor) to a member (holder) to cast that unit's ballot. Depth 1 only (D-14). |
| Represented | A unit with a `COUNTED` ballot, direct or by proxy. Quorum counts represented units (Q-1). |
| Contest | One election or one resolution on the meeting's agenda. |
| Election | Pick up to N of M candidates; mode `UNITS` (one vote per unit) or `WEIGHTED` (share bps per unit). |
| Resolution | YES / NO / ABSTAIN against a named threshold basis (§7). |
| Receipt | `SHA-256(ballot_id ‖ nonce ‖ canonical choices)`; given to the voter at cast time. |
| Commitment | `SHA-256(merkle_root ‖ contest_id ‖ canonical totals)`; published with the result. |
| Sealed link | The only table joining a ballot to its unit and caster; unreadable by the application after close (D-20). |
| Assessment | A dues charge or special assessment on a unit's ledger, integer cents, append-only. |
| Violation | A notice → hearing → fine/dismissed record with an event per transition (D-22). |

## 4. Ballot-level rules (closed set, precedence order)

A ballot is evaluated once, in `(cast_at, ballot_id)` order (B-4). The first rule that fires is the code; `""` means `COUNTED`.

| Code | Fires when |
|---|---|
| B-1 `UNKNOWN_UNIT` | `unit_id` not in the roster |
| B-2 `EARLY` | `cast_at < open_at` |
| B-3 `LATE` | `cast_at >= close_at` (the close instant itself is late) |
| P-1 `PROXY_UNKNOWN` | `via_proxy_id` set and not found |
| P-2 `PROXY_UNIT_MISMATCH` | proxy's `grantor_unit` ≠ ballot's `unit_id` |
| P-3 `PROXY_GRANTOR_NOT_OWNER` | grantor not an owner of record of the unit as of the record date (E-1) |
| P-4 `PROXY_LATE` | `received_at >= close_at` **or** `received_at > cast_at` |
| P-5 `PROXY_REVOKED` | `revoked_at` set and `revoked_at <= cast_at` |
| P-6 `PROXY_CHAIN` | `cast_by` ≠ holder and some proxy has `grantor_owner = holder`, `holder_owner = cast_by` |
| P-7 `PROXY_HOLDER_MISMATCH` | `cast_by` ≠ holder, no chain |
| P-8 `PROXY_HOLDER_NOT_MEMBER` | `rules.proxy_holder_must_be_member` and the holder owns no unit as of the record date (E-2) |
| E-6 `NOT_OWNER` | direct ballot; `cast_by` not an owner of record of the unit (E-1) |
| E-7 `INELIGIBLE_DELINQUENT` | `rules.delinquency_suspends_voting` and the unit's balance as of the record date > 0 (E-4, E-5) |
| E-8 `DUPLICATE_UNIT` | the unit already has a `COUNTED` ballot (B-4 first valid cast wins; equal `cast_at` → lower `ballot_id`) |

A malformed `cast_at` is `INPUT_INVALID` (raised, not a reject code); the database enforces the format in Phase 2. A rejected ballot still gets a receipt and is a leaf in the Merkle root (D-11).

## 5. As-of rules

| Code | Rule |
|---|---|
| E-1 | Owners of a unit as of date D: ownership rows with `from_date <= D` and (`to_date` empty or `to_date > D`). `[from, to)`. |
| E-2 | Member as of D: owner of at least one unit under E-1. |
| E-3 | Share as of D: the row with the greatest `effective_from <= D`; later rows ignored; no row → `RULES_INVALID`. |
| E-4 | Balance as of D: Σ `CHARGE` + `FINE` − Σ `PAYMENT` over entries with `date <= D` (inclusive). Integer cents. |
| E-5 | Delinquent as of D: balance > 0. |

## 6. Selection-level rules

Applied to each contest on each `COUNTED` ballot. The ballot stays counted; only that contest's selection is affected.

| Code | Fires when | Effect |
|---|---|---|
| S-1 `BLANK` | selection missing, `null`, `""` or `[]` | resolution: counted as ABSTAIN (units and bps); election: no vote |
| S-2 `INVALID_CHOICE` | election value not a list of strings; resolution value not in {YES, NO, ABSTAIN} | VOID |
| S-3 `UNKNOWN_CANDIDATE` | any id not in the contest's candidate list | VOID |
| S-4 `DUPLICATE_CANDIDATE` | the same id twice | VOID |
| S-5 `OVERVOTE` | more than `seats` ids; exactly `seats` is a vote | VOID |

Precedence S-2 → S-3 → S-4 → S-5. A key that names no contest is counted in `unknown_contest_keys` and ignored. Canonical choices (C-1) are computed from the ballot **as cast**, including void selections, so the receipt covers what the voter submitted.

## 7. Quorum and thresholds

**Quorum (Q-rules).** Q-1: a unit is represented when it has one `COUNTED` ballot, direct or by proxy. Q-2 units: `units_represented × 10000 >= threshold_bps × total_units`. Q-3 weighted: `bps_represented × 10000 >= threshold_bps × total_share_bps`. Q-4: `rules.quorum.basis` picks which binds; both are reported, plus direct-only under Q-2. No quorum → every contest's result is `NO_QUORUM`; totals and commitments are still computed (T-11).

**Resolution bases (T-1..T-6), all integer inequalities.** `yes`/`no` are unit counts, `yes_bps`/`no_bps` share sums, `rep` = units represented, `N` = total units (120), `S` = total shares (10000).

| Code | Basis | Passes iff | Abstain |
|---|---|---|---|
| T-1 | MAJORITY_OF_VOTES_CAST | `yes × 2 > yes + no` | excluded |
| T-2 | MAJORITY_OF_UNITS_REPRESENTED | `yes × 2 > rep` | counts against |
| T-3 | MAJORITY_OF_ALL_UNITS | `yes × 2 > N` | counts against |
| T-4 | TWO_THIRDS_OF_VOTES_CAST | `yes + no > 0` and `yes × 3 >= 2 × (yes + no)` | excluded |
| T-5 | MAJORITY_OF_WEIGHTED_SHARES_CAST | `yes_bps × 2 > yes_bps + no_bps` | excluded |
| T-6 | TWO_THIRDS_OF_ALL_WEIGHTED_SHARES | `yes_bps × 3 >= 2 × S` | counts against |

A tie is a fail under every majority basis. The eval prints pass/fail under all six next to the binding one (D-16) **[verify: which basis a real association uses is in its declaration and state statute; this project takes it from rules JSON]**.

**Elections (T-7..T-11).** T-7: plurality; each selected candidate receives 1 (UNITS) or the unit's bps as of the record date (WEIGHTED). T-8: rank by votes; let `v` be the votes of the candidate in position `seats`; candidates above `v` are elected; candidates at `v` are elected only if they exactly fill the remaining seats, otherwise those seats are `TIE_UNRESOLVED` with the tied ids listed (a zero-vote tie is still a tie). T-9: ties are never broken by the machine. T-10: the other mode is always computed as informational with a `differs` flag. T-11: `NO_QUORUM` overrides the result label only.

## 8. Receipts, commitments, the sealed link

| Code | Rule |
|---|---|
| C-1 | Canonical choices: JSON with sorted keys, `separators=(",", ":")`, ASCII; any list of strings sorted ascending. |
| C-2 | Receipt: `SHA-256(ballot_id + "\|" + nonce + "\|" + canonical)`, lowercase hex. Nonce: 128 random bits as 32 hex chars, generated at cast time, shown to the voter once, stored only as `SHA-256(nonce)` after close. |
| C-3 | Merkle root over **every received ballot**: leaves `SHA-256(receipt)` sorted ascending; parent `SHA-256(left_hex + right_hex)`; an odd node is carried up unchanged; root of nothing is `SHA-256("")`. |
| C-4 | Contest commitment: `SHA-256(root + "\|" + contest_id + "\|" + canonical totals JSON)`; totals are `{"UNITS":{…},"WEIGHTED":{…}}` for elections and `{"bps":{…},"units":{…}}` for resolutions. |
| C-5 | Meeting commitment: `SHA-256` of the contest commitments joined by `"\|"` in contest-id order. |
| C-6 | Published list: `(receipt, ballot_id, status, code, canonical choices)` sorted by receipt; no unit, no caster, no timestamp. Anyone recomputes C-3..C-5 and the totals from it. |
| C-7 | Verification: a voter checks their receipt appears in the list (and, holding the nonce, can recompute it from their ballot id and choices). |

What this proves and does not prove (D-2): a receipt in the root proves the ballot was included as cast; a recount from the list proves the published totals; nothing here hides how a voter voted from someone the voter shows the receipt and nonce to. **Not coercion-resistant, not receipt-free.**

**Sealed link (Phase 2, D-20).** `BallotSecret` holds `(ballot_id, unit_id, cast_by, via_proxy_id)`. Rules B-1..E-8 run at cast time against the live roster and write `status`/`code` onto the `Ballot` row with `unit_hash`, `bps_as_of`, `cast_at`, `choices`, `receipt`. At close a trigger revokes `SELECT` on `BallotSecret` from the application role. The Phase 2 recount entry point takes `Ballot` rows alone and must reproduce the Phase 1 engine's totals and commitments on the fixture. Tamper test: after close, the app role's `SELECT` fails; an `UPDATE` on any `Ballot` is rejected by trigger.
